# RUNBOOK 模板

**用法**:复制到 `campaigns/<战役名>/RUNBOOK.md`,替换 `<...>` 占位。
原则:subagent 读完这一份就能干活,**不需要向主 agent 追问任何登录方式**。
登录链路知识写在这里,不写进 prompt —— 这样不占主 agent 上下文,换机器也只改这一份。

派发时 prompt 里只需说四件事:cd 到哪、读这份 runbook、负责哪个分片文件、交付什么格式。

---

以下是模板正文(从这里开始复制):

# <战役名> Runbook

给 subagent 用的自包含操作手册。**不需要向主 agent 追问登录方式**,照此执行即可。

## 目标
对分配给你的 <节点/分片> 清单,逐项完成:
1. <步骤1,如:确认容器就绪>
2. <步骤2,如:跑 pytest 分片>
3. <步骤3,如:收集结果>

## 登录链路
本机 mac → `relay-cli proxy`(百度审计网关)→ 目标节点。当前用户免密,**用户名现场取**:

```bash
RUSER=$(ssh <ip> 'id -un')     # 不要在脚本里写死账号名
```

`~/.ssh/config` 里已有针对 `<网段通配>` 的段,含 `ControlMaster auto` + `ControlPersist 8h`,
socket 落在 `~/.ssh/sessions/`。**首次连某台会走一次 relay 指纹认证(慢,30-60s);
之后 8 小时内复用同一条通道,每条命令约 1s。**

不要自己拼 ssh 命令,统一用封装好的工具:

```bash
<工具> open  <ip>          # 建长连接(首次慢,之后秒回)
<工具> run   <ip> "<cmd>"  # 在长连接上跑一条命令
<工具> close <ip>          # 关闭长连接
```

工具在 `~/.local/bin/<工具>`。只读探测阶段它有**白名单硬拦截**(非只读命令 rc=99),
这是保护,不要绕过,也不要改这个脚本。

## 容器内执行

**你(本机 subagent)就是执行者。容器里起不了 ducx/baidu-codex,不要尝试。**
所有命令经 `ssh` + `docker exec` 下发:

```bash
ssh <ip> "docker exec <容器名> bash -lc '<命令>'"
```

**开工第一条必须自证落点**(避免把本机当成容器、结果作废 —— 有先例):

```bash
ssh <ip> "docker exec <容器名> bash -lc 'hostname; id -un; pwd'"
```

工作目录:容器内统一 `/workspace`(宿主机侧是 `/ssd<N>/$(id -un)`,N 由体检阶段定)。
**绝不在 home 或根分区下建工作目录。**

**不要内联长脚本** —— here-doc 和引号转义会反复出错。用 `docker cp` 把脚本送进容器再执行。

## 写权限边界(硬约束,越界即停)

机器是**共享的**,`/klxlake` 是全集群共享存储。一次越界写能毁掉别人几天的训练。

**宿主机上你只许做这三类写操作:**
1. `docker pull <image>`
2. `docker run` / `start` / `exec` —— 只针对**本战役自己创建的**容器
3. `mkdir -p /ssd<N>/$(id -un)/<战役目录>` —— 仅为挂载准备工作目录

宿主机上**禁止**:装包(`apt`/`pip`)、改 `/etc/**` `~/.ssh/**` `~/.bashrc`、
删改任何既有文件、动别人的容器、`docker system prune`、`kill` 不是自己起的进程。
**盘不够就换机器,绝对不许"顺手清理"共享机的盘。**

**容器内只许写 `/workspace`:**

| 路径 | 权限 |
|---|---|
| `/workspace` | ✅ 唯一可写区(代码、产物、日志全放这) |
| `/ssd1`~`/ssd4` 里其他用户的目录 | ❌ 禁写 |
| `/klxlake` | ❌ **禁写**,全集群共享 |
| 其他用户 home | ❌ 禁写 |

例外:环境初始化(`bcecmd` / `restore.sh`)会写容器内 `/usr/sbin/`、`~/.go-bcecli/`、
`~/.ssh/` —— 容器内 root 允许;同样操作在宿主机上禁止。

**需要越界写时:停下来报告,不许自行变通。**
"为了跑通顺手改了个全局配置"是本战役最严重的违规。
任何触碰边界的尝试都要写进 handback 的"异常与偏离"。

## 日志:远端存全量,元信息必须回传

**完整测试日志留在远端**(不回传,太大):
`/workspace/<战役名>/logs/<分片名>.log`,用 `2>&1 | tee` 落盘。

**但下列数据必须回传本机**,写成 `campaigns/<战役名>/handback/<阶段>-<节点>-<分片>.md`,
**格式严格照 `HANDBACK-schema.md`**(用户要逐条 review):

- 机器:ip、`hostname` 实际输出、根分区/数据盘剩余、`nproc`、load、同机他人任务
- 工作目录:宿主机 `/ssd<N>/<user>` + 容器内 `/workspace` + 选这块盘的理由
- 容器:name、image **实际 tag**、container id、落点自证命令的原始输出
- **进容器后逐条执行的命令原文 + rc + 耗时 + 输出摘要**(一条一行,不省略、不美化、
  失败和重试的也要写)
- 测试结果:pass/fail/skip 计数、单例平均耗时、失败用例清单
- 远端日志的**绝对路径 + `wc -l` 行数 + `md5sum`**(让人事后能定位和验真)
- 异常与偏离:任何和本 runbook 不一致的地方,没有就写"无"

纪律:
- 数字**抄命令输出**,不估算不换算
- 凭据一律写 `<REDACTED>`,AK/SK、token、密码绝不进 handback
- 必须 `cd <战役目录>` 后再执行,保证 handback 落在同一处
- **不许只回一句"完成了"** —— 没有 handback 文件等于没干活

## 执行纪律
- **写操作严格按上文「写权限边界」** —— 宿主机只许 docker 三类 + 建自己的工作目录;
  容器内只许写 `/workspace`。越界前停下来报告。
- **串行**跑你自己那一片,不要在片内再并发。同时压 relay 会超时
  (症状:`dial tcp ...: i/o timeout` 或 `Connection timed out during banner exchange`)。
- 单项失败**最多重试 1 次**,然后记下失败原因原文摘一句、跳过,继续下一项。
- 不要动 `~/.ssh/config`、不要改工具脚本、不要碰清单外的机器。
- <本战役特有的约束,如:不要删除任何测试产物 / 不要重启容器>

## 交付格式
按 `HANDBACK-schema.md` 交 handback 文件(**这是主交付物**),
另外在对话里回一段 markdown 表格做速览,列:

`| <项> | <标识> | <状态> | <关键指标1> | <关键指标2> | 备注 |`

失败的也要列出来,备注写失败原因(原文摘一句)。
数字直接抄命令输出,**不要换算不要估算**。
表格后附 3-5 行你观察到的共性。
